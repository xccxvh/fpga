# UDP 图片自适应与 FPGA HDMI 显示完整流程

本文说明如何把普通图片转换成 RGB565、调整为 HDMI 屏幕需要的
1280×720、通过 UDP 发送到 FPGA，并由 FPGA 写入 DDR3 后输出到 HDMI。

## 1. 整体数据流程

```text
JPG/PNG 原图
    │ img_to_rgb565.py
    ▼
源尺寸 RGB565 .bin（例如 3840×2160）
    │ resize_bin.py
    ▼
1280×720 RGB565 .bin（固定 1,843,200 字节）
    │ udp_send_image.py（1440 个 UDP 包）
    ▼
FPGA RGMII → MAC/IP/UDP → 跨时钟 FIFO → DDR3 framebuffer
    │
    ▼
DDR3 读出 → RGB565 转 RGB888 → HDMI 1280×720
```

FPGA HDMI 输出固定为 1280×720，因此发送文件必须正好包含：

```text
1280 × 720 × 2 Byte = 1,843,200 Byte
```

RGB565 文件采用小端字节序，像素顺序为从左到右、从上到下。

## 3. 一次性准备 FPGA

进入 FPGA 工程并编译：

```bash
cd "/media/rwj/ZX1 2TB/FPGA2026/udp_image_demo/fpga"
./build.sh
```

编译成功后生成：

```text
/media/rwj/ZX1 2TB/FPGA2026/udp_image_demo/fpga/outflow/ddr3_hdmi_test.bit
```

在 Efinity Programmer 中选择该 bitstream，通过 JTAG 烧录到开发板。
连接网线和 HDMI，并确认开发板与显示器已经上电。

板上两个 LED 的含义：

- `b_led[0]`：DDR3 校准完成。
- `b_led[1]`：HDMI 显示读 FIFO 已启动。

LED 只能说明 DDR/显示部分启动，不代表 UDP 图片一定已经收到。

## 4. 配置电脑有线网卡

FPGA 使用以下固定网络参数：

```text
FPGA IP   : 192.168.0.2
电脑 IP   : 192.168.0.3
UDP 端口  : 8080
```

先查找有线网卡名：

```bash
ip -br link
```

假设网卡名为 `enp3s0`，配置地址：

```bash
sudo ip link set enp3s0 up
sudo ip addr add 192.168.0.3/24 dev enp3s0
```

如果提示地址已经存在，可以忽略。检查配置：

```bash
ip -br addr show enp3s0
ip route get 192.168.0.2
```

目标地址应通过这块有线网卡直接到达，不能被 Wi-Fi 或其他路由抢走。

## 6. 让已有 RGB565 BIN 自适应屏幕

进入 PC 工具目录：

```bash
cd "/media/rwj/ZX1 2TB/FPGA2026/udp_image_demo/pc"
```

处理本次 `logo.bin`：

```bash
python3 resize_bin.py \
  "/media/rwj/ZX1 2TB/FPGA2026/image_tools/out/logo.bin" \
  "/media/rwj/ZX1 2TB/FPGA2026/image_tools/out/logo_1280x720.bin"
```

脚本会自动读取 `logo.bin.json` 中的 3840×2160 源分辨率。

如果输入文件旁没有 `.bin.json`，必须手动指定源分辨率：

```bash
python3 resize_bin.py 输入.bin 输出_1280x720.bin \
  --src-width 1920 --src-height 1080
```

### 自适应模式

| 模式 | 行为 | 适用情况 |
|---|---|---|
| `smart` | 默认最多拉伸 20%，剩余位置补黑边 | 兼顾铺屏和较小变形 |
| `stretch` | 强制拉伸为 1280×720 | 必须全屏且能接受变形 |
| `contain` | 完全保持比例，完整显示，可能有黑边 | 不能裁剪或变形 |
| `cover` | 保持比例铺满，居中裁掉超出部分 | 不要黑边且不能变形 |

例如强制铺满：

```bash
python3 resize_bin.py 输入.bin 输出.bin --mode stretch
```

调整 `smart` 模式允许的最大拉伸程度：

```bash
python3 resize_bin.py 输入.bin 输出.bin --max-stretch 1.10
```

`1.10` 表示最多修正约 10% 的宽高比例；默认值为 `1.20`。

  --gap 0.001

## 8. UDP 分包过程

每个 UDP payload 由 16 字节自定义包头和最多 1280 字节图像数据组成：

```text
magic + frame_id + packet_idx + total_pkts
+ payload_len + reserved + byte_offset
+ RGB565 data
```

1280 字节数据等于 640 个 RGB565 像素，也等于 80 个 DDR3 128-bit beat。
完整一帧共 1440 包。`byte_offset` 告诉 FPGA 当前数据应该写到 framebuffer
的哪个字节地址，因此每个 UDP 包可以写入对应的图像位置。

## 9. 常见问题排查

### 发送完成但屏幕没有变化

“发送完成”只代表 Linux 已经把 UDP 数据交给网卡，不保证 FPGA 已收到。
检查 ARP：

```bash
ip neigh show 192.168.0.2
```

如果状态为 `INCOMPLETE` 或 `FAILED`，优先检查网线、PHY、电脑网卡地址和
FPGA bitstream。

抓取 ARP、ICMP 和 UDP 报文：

```bash
sudo tcpdump -ni enp3s0 'arp or icmp or udp port 8080'
```

把 `enp3s0` 换成实际有线网卡名。

### 画面尺寸或文件大小不正确

检查元数据：

```bash
cat "/media/rwj/ZX1 2TB/FPGA2026/image_tools/out/logo_1280x720.bin.json"
```

检查文件大小：

```bash
stat -c '%s %n' \
  "/media/rwj/ZX1 2TB/FPGA2026/image_tools/out/logo_1280x720.bin"
```

必须是 `1843200` 字节。

### 颜色异常

确认转换和自适应步骤都使用默认的 `little` 字节序。FPGA 当前按 RGB565
小端数据读取。不要给 `resize_bin.py` 或转换脚本传入 `--endian big`。

### 画面有缺块或撕裂

先使用更大的包间隔：

```bash
python3 udp_send_image.py 图片.bin --gap 0.001
```

若仍异常，再检查 UDP 是否丢包、DDR3 校准 LED 和 FPGA 接收逻辑。
